# 项目维护说明

本文档用于约束项目目录、统一版本号和发布流程，避免开发副本、历史构建产物和正式发布文件混在一起。

## 正式源码目录

当前正式源码目录为仓库根目录，也就是 `提词器-整理版-6.0`。后续开发、提交 GitHub 和本地打包都应以这个目录为准。

## 平台策略

- **Tauri 版是主力版本**，支持 Windows、macOS、Linux。新功能、Bug 修复和平台适配都以 Tauri 版为准。
- **Electron 版是 Windows 备用版本**，只同步共享前端，不再扩展到其他平台，也不单独开发新功能。
- 与平台相关的原生逻辑集中在 `tauri/src-tauri/src/lib.rs`，需要分平台处理时用 `cfg!(target_os = ...)` 并写明原因（例如 macOS 第二屏使用 simple fullscreen，避免原生全屏切到独立 Space）。

## 目录职责

```text
.
├── tauri/               Tauri 桌面版源码（全平台，主力维护）
├── windows-electron/    Electron 桌面版源码（仅 Windows，备用）
├── scripts/             版本同步和检查脚本（Node.js）
├── tests/               Playwright 自动化测试
├── docs/                打包、发布、更新日志和维护说明
├── VERSION              当前统一产品版本号
├── README.md            项目总说明
└── 使用指南.md          用户使用说明
```

## 不提交的内容

以下内容不应进入源码仓库：

- `node_modules/`
- `dist/`
- `target/`
- 安装包和便携包，例如 `.exe`、`.msi`、`.zip`
- 临时日志、测试截图和系统文件

这些规则已经写入 `.gitignore`。正式发布包由 GitHub Actions 上传到 GitHub Release，不放进源码仓库。

## 版本号规则

Tauri 版和 Electron 版使用统一产品版本号。当前版本写在 `VERSION`，现在为 `6.5.0`。

修改版本号时运行：

```bash
npm run sync:version -- 6.5.0
```

版本同步后运行完整检查：

```bash
npm install
npm run check
```

脚本会同步 Tauri / Electron 的 `package.json`、`package-lock.json`、Tauri `Cargo.toml`、`Cargo.lock`、Tauri 配置和前端页面里的短版本号。`npm run check:version` 会检查以上所有位置是否一致。维护脚本统一在 `scripts/project.mjs` 中，只依赖 Node.js，Windows、macOS、Linux 通用。

## 前端同步规则

当前 Tauri 和 Electron 的入口页面内容保持一致：

- Tauri 主窗口加载 `tauri/web/index.html`
- Tauri 第二屏通过 `index.html?mode=output` 进入输出模式
- Electron 加载 `windows-electron/index.html`

修改前端界面或提词逻辑时，优先修改 `tauri/web/index.html`，然后运行：

```bash
npm run sync:frontend
node scripts/project.mjs check-parity
```

## 自动发布

### 发版步骤

1. 在 `docs/更新日志-X.Y.md` 中写好 `## X.Y.Z` 小节（新的次版本号就新建文件，格式参考已有日志），提交并推送到 `main`。这一节会直接作为 GitHub Release 的说明，缺失时发版会在第一步失败。
2. 打开 GitHub 仓库的 **Actions → Release → Run workflow**，填写版本号（例如 `6.6.0`）。勾选"草稿"会先创建草稿 Release，检查无误后再在 GitHub 上手动发布。
3. 工作流自动完成：
   - 校验版本号格式、不低于当前版本、标签不存在，且更新日志中有对应小节
   - 同步全部版本号位置，提交 `release: prepare version X.Y.Z` 到 `main` 并打 `vX.Y.Z` 标签
   - 在 Linux 上执行 `npm run check`
   - 并行构建全部安装包（见下表）
   - 生成 `SHA256SUMS.txt`，以更新日志小节加下载说明作为正文，创建 GitHub Release

也可以在本地运行 `npm run sync:version -- X.Y.Z`、提交后推送 `vX.Y.Z` 标签，工作流会跳过版本提交，直接构建并发布。

重跑失败的发版工作流时，已存在的 Release 会被更新，同名文件会被覆盖。

### 构建产物

| 平台 | 文件 |
| --- | --- |
| Windows x64 | `Teleprompter-Tauri-X.Y.Z-Windows-x64-Setup.exe` |
| Windows ARM64 | `Teleprompter-Tauri-X.Y.Z-Windows-arm64-Setup.exe` |
| macOS（通用） | `Teleprompter-Tauri-X.Y.Z-macOS-universal.dmg` |
| Linux x86_64 | `Teleprompter-Tauri-X.Y.Z-Linux-x86_64.AppImage`、`-Linux-amd64.deb`、`-Linux-x86_64.rpm` |
| Linux ARM64 | `Teleprompter-Tauri-X.Y.Z-Linux-aarch64.AppImage`、`-Linux-arm64.deb`、`-Linux-aarch64.rpm` |
| Windows x64（Electron 备用） | `Teleprompter-Electron-X.Y.Z-Windows-x64-Portable.exe`、`-Setup.exe` |

### 工作流文件

- `.github/workflows/build.yml`：检查和全平台构建，只上传构建产物。每个 PR 都会运行，也可以在 Actions 页面手动运行。
- `.github/workflows/release.yml`：发版。准备版本和标签，调用 `build.yml` 构建，再发布 Release。

当前工作流默认生成未签名安装包（macOS 为 ad-hoc 签名，未公证）。接入 Windows 代码签名证书或 Apple Developer ID 后，应将证书配置放入 GitHub Actions Secrets，并在构建步骤中增加签名流程，不要把证书文件或密码提交到仓库。
